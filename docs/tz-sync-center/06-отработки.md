## 1. Одна формула, чистое ядро

`src/data/crm-makeup-seats-core.ts` — без fs, без Alfa.

```ts
makeupCap(opts: {
  limit: number;
  cgiLive: number;      // is_study=1 в cgi этой группы, не лиды, не гости makeup
  makeupsHere: number;  // тип 4, эта дата, этот groupId, статус не отмена
  extra: number;        // policy.makeup.extra, 0–10
}): { ok: boolean; spare: number; reason: string }
```

```
cgiLive + makeupsHere ≤ limit + extra
spare = (limit + extra) - cgiLive - makeupsHere
```

Особые:

- `limit <= 0` → `ok: false`, `reason: "no-limit"` — **не записывать молча**.
- `makeup.perLesson === false` только с предупреждением в UI этапа 1; если false — считать по группе без даты (не завод). Завод true: счёт **на урок (дата+groupId)**.
- Тип 10 extra и 11 overtime в `makeupsHere` **не** входят.
- Гость makeup **не** увеличивает `cgiLive`.
- Лид в `taken` **не** в `cgiLive`.
- Смена `extra` **не** пересчитывает и не снимает уже стоящие отработки; новые записи — по новому extra.

Примеры (завод extra=2):

| limit | cgiLive | makeups | результат |
|---|---|---|---|
| 10 | 7 | 0 | spare 5; 6-я запись отказ |
| 10 | 10 | 0 | spare 2; 3-я отказ |
| 10 | 7 | 4 | spare 1; ещё одна ок, дальше нет |
| 10 | 6 + 4 лида в taken | 0 | cgiLive=6, spare 6; витрина может быть «мест нет» |
| 0 | 5 | 0 | отказ |

## 2. Откуда числа на диске (не Alfa в формуле)

Сборщик `crm-makeup-seats.ts`:

**cgiLive** — живые `is_study=1` в cgi / `groupLinks` этой группы. Не `slot.taken`. Не `takenLead`. То же, что ночной inbound cgi как состав.

**makeupsHere** — календарь группы (`loadGroupCard.calendar`) + индекс коллег этапа 5: уроки `typeId===4` (или kind makeup), `groupId` совпал, дата урока = дата слота, status ≠ отмена.  
`customerIds` гостей уникально. Свой customer уже на слоте — ok идемпотентно, не +1.

Нет карточки / нет календаря: `makeupsHere` из occupancy; если и его нет — 0, не выдумывать. Не ходить в Alfa «на всякий» в `book_lesson`.

**limit** — `slot.limit` / карточка группы. Не `taken`.

## 3. Витрина vs makeup

Два текста мест, не один `seatsText` на всё.

| Режим | Функция | «мест нет» |
|---|---|---|
| Постоянная запись `kind=group` | как сейчас `limit - taken` (с лидами) | прятать / не записывать |
| Отработка `kind=makeup` | `makeupCap` → spare | **не** прятать, пока `spare > 0`. Текст: `ещё N на отработку` / `отработок нет` |

`slotChips(..., "makeup")` и `rankMakeupSlots`: фильтр не витринное «мест нет», а `makeupSpare(g, date) > 0` (и priority ≠ 0, не свой gid).

`ownGid`: не в пуле (`!g.ownGid`). `makeup.ownGid` завод false — консультанту отказ «не в свою группу». Админ руками на свой gid — формула всё равно считает.

`fullGroupOk` завод true: `taken >= limit` не скрывает makeup. Если админ выкл — как сейчас по витрине.

`offerSlots` (1–8, завод 3): `pageMakeup(..., size)` и playbook «три слота» читают политику, не хардкод 3. Сценарий недель **не** переписывать.
