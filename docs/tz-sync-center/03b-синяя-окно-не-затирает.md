## Гипотеза «месяц → два → четыре → всё» — где ломается

Окно дат **нельзя** давать переписи и prune. `pruneCalendarToAlfaIds` оставляет только id из переданного множества (+ hold + `lessonId < 0`). Перепись за 30 дней + prune снимет всю историю старше окна. Это не extra, это порча диска.

Окно 1 / 2 / 4 месяца — **только тела** недостающих id (`inboundMissingCustomerLessons`), если полная перепись уже сказала «этих номеров нет на диске». Не для счётчика. Не для обрезки.

Полная перепись (index по `customer_id`, статусы 3/1/2, все филиалы) — обязательна, иначе `lessonsAlfa` врёт и extra не отличить от дырки.

## Ошибки, уже в коде (не выдумка)

1. **Потолок 12 страниц × 100.** `censusCustomerLessonIds`: `page < 12`. Если на 12-й странице ещё 100 строк — цикл кончается, `ok: true` (`canCloseLessonCensus({ live: true, aborted: false })`). Перепись обрезана, prune по ней сотрёт хвост. Закрывать перепись нельзя, пока последняя страница полная.

2. **3a vs выкладка `937c2ee`.** 3a: «census синей не пишет `uniq.length` в обход». Сейчас `applyCustomerLessonCensus` пишет живой `uniq.length`. Закон развести: **проба / «Добрать» / сорванная перепись = keep (3a).** **Закрытая полная перепись синей = живое число (3b).** Молчание по-прежнему не пишет.

3. **Fan-out не в `customer_id`.** `inboundJournalGroup` / карточка урока пишут ученику урок, где она в `pupils` / `customer_ids`. Перепись синей — только `lesson/index?customer_id=cid`. Если Alfa в индексе ученика этого id нет, а на диске группы он есть — prune снимет чужую качку. Extra Галкиной 172/171 — этот класс, пока не доказан id.

4. **Замок ученика не общий.** `inboundCustomerLessons` берёт `waitLockStudentAlfa`. Журнал группы и `fanOutLessonWriteoffs` — нет. Синяя prune параллельно с пакетом Фон `journal` может выкинуть id, который группа только что посадила.

5. **Синяя сейчас качает тела с 2015** (`recheck` → `inboundCustomerLessons` full × 6, `prune: false`), потом census, потом prune. Качка тел для extra не нужна: лишний id уже на диске.

6. **Hold** спасает только очередь `lesson.update` / `lesson.create` и `lessonId < 0`. Чужой Alfa-id с группы в hold не попадает.

7. **`countAlfaLessonRows` ≠ unique переписи.** После collapse это строки с `lessonId>0`. Две строки одного id — extra без нового занятия. Prune по id это не лечит, лечит collapse (уже в `saveCustomerCalendarList`).

## Закон синей (один путь, не второй мозг)

Файл: `pullOneStudent(..., recheck=true)` + `censusCustomerLessonIds` + `applyCustomerLessonCensus`.  
Не трогать: красную `if (!recheck)`, missing на «Добрать», Фон пакеты сами по себе.

### Шаг A — перепись, не журнал

- `date_from=2015-01-01`, все филиалы, статусы 3/1/2.
- Страница 100. **Полная последняя страница (length=100) → не закрывать**, `ok: false`, aborted. Keep 3a.
- 429 / catch страницы → `ok: false`. Keep. **Prune запрещён.**
- `ok: true` только если ни один цикл не оборван и ни одна последняя страница не полная.

### Шаг B — сверка, без inbound тел

- `disk = countAlfaLessonRows(календарь cid)` после collapse.
- `alfa = uniq.length` закрытой переписи.
- Равенство → `mark` закрытие, `lessonsRecheckAt`. Тела не качать.
- Диск > Alfa → шаг C (снять лишнее), не полный inbound.
- Диск < Alfa → шаг D (missing id), не с 2015 пачками take:8.

### Шаг C — что синяя имеет право снять

Снимать `lessonId > 0`, которого **нет** в закрытой переписи, **и нет**:

- в hold очереди `lesson.update` / `lesson.create`;
- `lessonId < 0`;
- на календаре группы, где ученик в `groupLinks` / `pupils` / `customer_ids` этого урока (`loadGroupCard(branchId, groupId)`).

Id с группового диска — чужой загрузчик. Не prune. Extra может остаться: так и надо, пока группа и индекс ученика в Alfa не сойдутся.

Иначе (id только в личном календаре, Alfa по `customer_id` не знает) — снять.

После prune: `lessonsAlfa = uniq.length`, `lessonsDisk = count`, `lessonsFull` только при равенстве.

### Шаг D — дырка после закрытой переписи

Не полный `inboundCustomerLessons`.  
`missing = census.ids − disk.ids`.  
Тела: `inboundMissingCustomerLessons`, пачка как сейчас (cap 50).

Если missing пуст, а диск < Alfa — ложь счётчика vs collapse, не крутить 2015.

Окно дат на missing **не нужно**, если уже есть id. Окно 1/2/4 мес. — запасной путь, только если перепись не закрылась и человек всё же нажал синюю: тогда **только union inbound** окна, **без prune**. Не закрывать cid.

### Шаг E — чужие загрузчики

| Кто | Пишет календарь cid | Синяя |
|---|---|---|
| Фон пакет `lessons` | `inboundCustomerLessons(cid)` + штамп | замок `waitLockStudentAlfa` — ждать, не параллелить prune |
| Фон пакет `journal` | группа → fan-out, штампа cid нет | id на группе не prune (шаг C) |
| Кнопка группы / ДЗ / карточка урока | fan-out | то же |
| Пробный урок | `upsertCustomerCalendar`, часто id < 0 | hold / id < 0 |
| «Добрать» | inbound + missing + keep 3a | не этот путь |
| Ночь групп | состав, не журнал | не трогает |

Не второй файл расписания. Не вторая очередь. Не `syncAllFromCrm`.

## Приёмка на диске, не по имени

1. Перепись: последняя страница 100 → `ok: false`, календарь cid байт-в-байт, `lessonsAlfa` тот же.
2. cid, где extra = id, который есть в `group-cards` её группы и нет в переписи `customer_id` — после синей id **на месте**, extra может жить.
3. cid, extra = id только в личном календаре, перепись закрыта без него — id снят, `lessonsAlfa = uniq`, диск = alfa.
4. Фон `journal` во время синей: id, только что севший fan-out с группы, не исчез.
5. «Добрать» 17 / 2124: keep 3a как был.
6. Нет полного inbound с 2015 на синей, если перепись закрылась.

Простыми словами: синяя сначала считает номера в Alfa за всю жизнь. Журнал с 2015 не качает. С диска снимает только то, чего нет ни в Alfa у ученика, ни в журнале его группы, ни в очереди на выгрузку.
