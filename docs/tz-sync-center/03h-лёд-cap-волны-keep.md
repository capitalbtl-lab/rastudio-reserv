# ТЗ · ядро · синяя «История»: лёд, cap, волны, keep

**REV:** 2026-09-15-ice-cap-wave-keep  
**Ядро A.** Экран D не трогать. Ромашка-9 не трогать. Деплой — по фразе.

Учтены ловушки: красная тащит `dateTo` синей; resume по кругу правых; вечный жёлтый из‑за cap/`n >= total`; prune по короткому списку.

Цель. Синяя на старте записывает дни, все карточки этого прогона смотрят эту запись. Красная её стирает. Восемь отказов — «этот не вышел, налево», не смерть прогона. Счёт уроков не уменьшать и календарь не резать, пока окно АльфаСРМ не дочитали до конца. Вечный жёлтый при живой дыре в API лучше молча обрезанного диска.

## Поля джоба

В `emptyJournalJob` обязательно `dateTo: ""`. Иначе `mergeJobPatch` / `{ ...empty, ...raw }` сотрёт лёд: поля нет — при следующем save его нет на диске.

`dateTo` в типе **опционален**, чтобы сайт и воркер не разъехались до выкладки.

| | синяя | красная |
|---|---|---|
| `dateFrom` | лёд.from | как сейчас, часто `2015-01-01` |
| `dateTo` | лёд.to | всегда `""` |

Старт красной: `dateTo=""`, не тащить лёд прошлой синей.

Старт синей: перезаписать **оба** конца. Не оставлять `2015` у синей.

Пауза: `jobPeriodDays` / `recheckDays`. **Не** считать дни между `dateFrom` и `dateTo`.

## 1. Лёд

На `startJournalJob` синей: `win = recheckWindowYmd(clamp(opts.recheckDays))` **один раз**. Пишем `dateFrom`/`dateTo`. Дальше `now` не звать.

Труба, все четыре места:

```
job → historyLoadOne → journalPull → (pullOneStudent | pullOneGroup / inboundJournalGroup | inboundCustomerPays)
```

Правило одно: синяя **и** оба конца непусты → окно = они, не `recheckWindowYmd(now)`.

Не дописать одно место — плывёт только оно (касса «сегодня», календарь «старт»).

Проверка: три вызова с одним джобом, часы +1 день — три окна равны полям джоба.

Resume: лёд с диска.

Старый джоб, `dateTo` пустой: если пусто — **один раз** посчитать, записать, ехать. Поле уже есть — не пересчитывать, даже если воркер рестарт.

Один клик по карточке: лёд на этот вызов (этот джоб), не на каждый урок внутри.

Шаг 1 cgi: `dateFrom`/`dateTo` в roster **не** подставлять.

Лёд от минуты старта (23:50): через 6 часов край окна не «сегодня−32» — так и надо.

## 2. Cap 8

`JOB_WAIT_CAP = 8`, не поднимать.

После 8 сбоев на cid:

* `idx + 1`, `waits: 0` (иначе resume мёртв), `n` не как успех.
* `running: true`, если есть ещё `items` **или** `advanceJobWave` даст пачку.
* нет ни того ни другого → стоп, «Остановились».

Последний правый с cap → левые. Этот правый остаётся жёлтым. «Прошло n / total» может быть 79/80 — не дыра календаря.

Один человек в пачке, волны нет → стоп.

Того же cid после cap не крутить.

Шаг 4, последний в кассе, волн нет → конец шага 4. На шаг 5 сами не идём.

---

## 3. Волны

Режимы: `people-recheck`, `groups-recheck`, `roster-recheck`.

После успеха или cap **не** ставить `running: false`, пока не выполнен `idx >= length` → `advanceJobWave`.

`shouldResumeStalledJob` для этих трёх:

* `stop` → нет.
* stall-таймер как сейчас (`RECHECK_STALL_MS`).
* не отказывать только из‑за `n >= total`.
* поднять, если `advanceJobWave` (wave/follow с диска) вернёт пачку.
* не поднимать, если `advance == null` и `idx >= length` — штатный конец. Иначе pm2 по кругу правых.

На штатном конце: не оставлять «живой» `wave`, из‑за которого resume выдумает пачку. Писать `wave: "right2"`, `follow: []`.

`doneMsg` синей — «N перепроверили». `/готово/i` её не режет — **не чинить текстом**.

Шаги 4–5 колонками не волнуют (свой `people-recheck` кассы живёт, на шаг 5 сами не идём).

## 4. `lessonsAlfa` — только шаг 2 синяя

`windowAlfaKeep = keep + севшие новые − ушедшие`.

Минус keep, prune окна, gone — все три **только если**:

* перепись окна ok и страницы дочитаны: сумма `items.length ≥ total` (не `page*100`, не «пачка < 100» в одиночку);
* статусы 1, 2 и 3 как сейчас;
* не `journalHoleApprovedAt`;
* gone = id в окне на диске, которых нет в этой закрытой переписи, не hold, не group-card.

Иначе (обрыв, 429, `total>0` и пустые `items`, `ok:false`): keep не снижать, prune не делать, missing только по id, которые перепись отдала. Keep может остаться завышен — жёлтый жив. Молча резать диск нельзя.

Плюс keep — только число **севших** строк, не dropped, не «новые до посадки».

`applyCustomerLessonCensus(..., closed)`: `closed=true` только при дочитанных страницах. Иначе не звать с `true` (сейчас `!closed` уже не prune — не сломать).

Галка: keep и prune не трогать. Prune при галке запрещён — иначе строки съест, галка не спасёт.

`uniq.length` окна в `lessonsAlfa` не писать. `keepAlfaProbe(..., census)` на окне не включать.

Шаги 1, 3, 4, 5 `lessonsAlfa` так не пишут. Журнал группы шага 3 режется льдом, счёт ученика не синхронизировать с группой в этом ТЗ.

Pay-poll своё окно, файл кассы истории не читает — не смешивать.

## Приёмка (как ломается на тестах)

1. Один `startJournalJob`, два cid, часы +1 день между ними — `dateFrom`/`dateTo` джоба те же. Два старта подряд — не этот тест (второй перельёт лёд).
2. Три места (календарь, группа, касса) не зовут `recheckWindowYmd` при непустом льде.
3. Старт красной после синей: `dateTo === ""`.
4. Cap: пачка один правый + жёлтые слева (не два правых). После 8 сбоев — левые в `items`, `running`, `waits=0`.
5. Диск: `people-recheck`, `running:false`, `idx>=length`, `n>=total`, волна правых ещё в поле, слева есть жёлтые, advance дал бы пачку → resume да. После штатного `advance==null` (`wave:"right2"`) → resume нет.
6. Перепись окна `ok:false` или `items` пустые при `total>0` → `lessonsAlfa` ≥ keep, строки окна на диске на месте.
7. `clampRecheckDays(7) → 32`.

Простыми словами. Синяя на старте записывает дни и все карточки смотрят эту запись; красная её стирает. Восемь отказов — «этот не вышел, налево», не смерть прогона. Следующую колонку не начинать, только если колонок больше нет. Счёт уроков не уменьшать и календарь не резать, пока окно АльфаСРМ не дочитали до конца. Вечный жёлтый при живой дыре в API лучше молча обрезанного диска.
