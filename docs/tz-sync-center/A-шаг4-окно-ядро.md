## API Alfa

- 5 запросов/с. Общего limiter в коде **нет** — не плодить. Пауза 5 с между людьми.
- `lesson/index`: без `status` → 3. Явно 1, 2, 3. Даты `YYYY-MM-DD`. `id` в теле. `pageSize` переписи уже 500 (макс Alfa) — не менять на 100.
- `censusCustomerLessonIds` сам подставляет `date_from=2015-01-01` и `date_to=сегодня+90`, если пусто. На шаге 4 звать **только** с обоими YYYY-MM-DD окна.
- Минимум переписи: `uniqueBranches` (4) × `LESSON_STATUSES` (3) = **12** запросов на нулевые страницы. Потолок 8 перепись не закрывает — prune запрещён, окно бесполезно.
- `inboundMissing`: на каждый id до 4×3 запросов. Пачка 50 на шаге 4 запрещена.
- `pay/index`: `customer_id` + страница, даты `yyyy.mm.dd`. Окно уроков не передавать.

## Зачем

`if (!balance)` — уроков нет. Копировать синюю шага 2 нельзя: `wasLessonGreen` → 2015; missing 50 съедает 5/с; потолок 8 < 12.

## Шаг 1. Синяя `balance && recheck`

Один `waitLockStudentAlfa(cid)` на вызов. Не взяли — кассу не начинать. Unlock в `finally`.

1. Касса первая, `{ force: true }`, без дат урока. `PAY_INBOUND_*` не менять.
2. Журнал **только если `scanDone`**.
3. Окно: `clampRecheckDays(recheckDays)` → сегодня±N, оба конца YYYY-MM-DD. Не `recheckCensusWindow` / `wasLessonGreen`. Не 2015. Не `date_to` по умолчанию +90.
4. Только `censusCustomerLessonIds` + prune в окне + `keepAlfaProbe` / `windowAlfaKeep`. Галка: missing не звать.
5. **`inboundMissing` на синей шага 4 не вызывать.** Дырка — шаг 2.
6. Потолок: 4×3 = 12 страниц 0, дальше не листать (`pageCap` для шага 4 = 1). `ok` переписи — все 12 ответили. Иначе prune нет, `lessonsRecheckAt` нет.

`shouldRetryOpenRecheck(balance)` только `!paysRechecked`.  
`mark()` не пишет `paysAt` / `paysRecheckAt`. `lessonsRecheckAt` — только если hole=0, extra=0, rows=uniq.

## Шаг 3. Не менять

## Критерий A

1. `pay/index` до `lesson/index`.
2. Нет `scanDone` → уроков нет.
3. Синяя: `lesson/index` с `date_from` и `date_to` окна, не 2015, не +90 по умолчанию.
4. Синяя: нет вызова `inboundMissing`.
5. Красная: нет `lesson/index`.
6. В pay нет дат урока.
7. `status` 1|2|3 на каждом lesson.
8. `paysRecheckAt` после `scanDone`; очередь не сидит на short.
9. `admin-crm-settings.tsx` без диффа.

Простыми словами: шаг 4 качает кассу. Синяя после дочитанной кассы один раз переписывает уроки за ± месяц (12 запросов) и снимает ушедшие в окне. Дырки не добирает — это шаг 2.
