- `pay/index`: `customer_id` + `page` + `pageSize` 50. Даты платежей `yyyy.mm.dd` (`alfaPayIndexDate`). Окно уроков (`YYYY-MM-DD`) в pay **не передавать**.

- Филиал в URL. `uniqueBranches` как сейчас.

## Зачем

`if (!balance)` — шаг 4 не ходит в урок. `recheckDays` пустой.

Не копировать синюю шага 2 как есть:

1. `recheckCensusWindow` при `!wasLessonGreen` даёт пустое окно → в `pullOneStudent` `censusFrom = from` = **2015**. На шаге 4 синяя очередь — касса готова, журнал может быть жёлтым. Получится полный census с 2015 после кассы. Запрещено.
2. «Остаток 90 с» — это таймаут HTTP экрана. Воркер `tickJob` 90 с не знает. Журнал на шаге 4 — свой потолок запросов, не 90 с.
3. `force` кассы сбрасывает курсор, за тик 4 страницы. Если касса не `scanDone`, census после неё съедает лимит — касса на следующем тике снова ждёт. Журнал только после `scanDone`.

## Шаг 1. Синяя `balance && recheck`

Один `waitLockStudentAlfa(cid)` на весь вызов. Не взяли — выйти, кассу не начинать, `paysRechecked` нет (тот же id на следующем тике). Unlock в `finally`. Касса сейчас lock не берёт — обернуть.

1. **Касса первая**, как сейчас: `inboundCustomerPays` `{ force: true }`. Без дат урока, без `recheckDays`. `PAY_INBOUND_RUN=4` / 20 с не менять. Типы 5/6/9 и `ctt_id` не трогать.
2. **Журнал только если касса `scanDone` в этом вызове.** Иначе конец. `payFill` не сбрасывать.
3. Окно **всегда** `clampRecheckDays(recheckDays)` → `сегодня−N` / `сегодня+N` как `YYYY-MM-DD`. **Не** вызывать `recheckCensusWindow` с `wasLessonGreen`. **Не** 2015. Пустое окно — журнал не начинать.
4. Потолок журнала на шаге 4: не больше **8** вызовов `lesson/index` за тик (перепись+missing). Дальше стоп, prune только если перепись окна дочитана (`ok`). Missing не досидели — не ретраить шаг 4.
5. Статусы 1/2/3, prune в окне, `keepAlfaProbe` / `windowAlfaKeep`, галка, нет даты — dropped. Не полный fill.

`shouldRetryOpenRecheck(balance)` только `!paysRechecked`. Не `!rechecked`.

`mark()` не пишет `paysAt` / `paysRecheckAt`. Их блок кассы после `scanDone`. `lessonsRecheckAt` — только если журнал окна закрыт по id.

## Шаг 2. Красная `balance && !recheck`

Касса первая, lock тот же. Вправо `paysScanned || pays`. Не ±1 ₽.

Журнал только если `scanDone` **и** `lessonsStampShort` **и** нет галки: **одна** пачка missing, не больше 8 `lesson/index`, `dateFrom` YYYY-MM-DD, тела `{ id, status }`. Не fill. `shouldRetryShortPeople` для balance не включать.

Сошёлся или галка — урок не звать. `setsClosed` false — в пачку, не skip (03f).

## Шаг 3. Не менять

`peopleJobFinished(balance)`, `skipLeads`, `shouldRetryCash` красной, один `crm-pays.json`, шаг 5, `PAY_INBOUND_*`.

## Критерий A

1. `balance+recheck` бьёт `pay/index` до `lesson/index`.
2. Касса не `scanDone` → `lesson/index` нет.
3. Жёлтый журнал + синяя касса → окно ±N, в `lesson/index` нет `2015-01-01`.
4. В `pay/index` нет `date_from` урока.
5. `lesson/index` с `status` 1|2|3, даты YYYY-MM-DD.
6. Журнал не закрыт, pay `scanDone` → `paysRecheckAt` есть, очередь не ретраит по short.
7. Красная, журнал готов → только pay.
8. Checksum на `paysRecheckAt` не влияет.
9. `admin-crm-settings.tsx` без диффа.

Простыми словами: сначала платежи. Уроки — только когда касса за тик дочитана, и только за ± месяц, не с 2015. Очередь кассы из-за дырки уроков не встаёт.
